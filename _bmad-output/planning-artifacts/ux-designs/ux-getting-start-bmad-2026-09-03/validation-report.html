SchoolDesk — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-getting-start-bmad-2026-09-03/

The SchoolDesk spine pair is structurally sound — canonical section order, all required EXPERIENCE defaults present, sources resolve. But as a consumer contract it carries significant gaps. Two load-bearing token contradictions in DESIGN.md (badge filled vs tinted, skeleton background vs border) would produce incorrect UI if implemented from frontmatter. Four of six user journeys lack dedicated key flows. The accessibility floor is well-intentioned but broken by the badge token mismatch, a non-compliant timer warning color, missing focus traps in exam full-screen mode, and the role="application" anti-pattern. Edge cases around permission boundaries, race conditions in concurrent grading, offline conflict resolution, and empty states for less-common surfaces are largely undefined. The happy paths are solid; the "what breaks" paths need reinforcement before story-dev picks this up.

Cross-referencing all three lenses: the badge token contradiction is the single most dangerous finding — it appears in rubric, accessibility, and is the root cause of the critical contrast failure. Resolving it (aligning frontmatter to the tinted-background prose spec) would eliminate findings across all three reviewers.

1. Flow coverage

THIN

The PRD defines 6 Key User Journeys (UJ-1 through UJ-6). EXPERIENCE.md ships exactly 2 Key Flows, both well-formed (named protagonist, numbered steps, climax beat, failure path). The remaining four journeys have no dedicated key flow.

HIGH

Four UJs have no dedicated Key Flow

EXPERIENCE.md §Key Flows vs prd.md §2.3
UJ-1 (daily classes glance), UJ-2 (view student info), UJ-3 (create exam schedule), UJ-6 (check results) have no Key Flow. Only UJ-4 (grades) and UJ-5 (takes exam) are realized as flows.
Fix: Add 2–4 short flows or annotate existing flows as realizing specific UJs so every UJ has a named, step-numbered, climax-bearing walk.
MEDIUM

No flow annotated to UJ/FR

EXPERIENCE.md §Key Flows
No flow is tagged with the UJ/FR set it covers. A downstream story-dev cannot tell which journey a flow is the contract for.
Fix: Tag each flow header with the UJ/FR set it covers.
MEDIUM

Persona drift from source PRD

EXPERIENCE.md lines 159, 169
PRD uses "Ms. Rivera (student)" for UJ-5/6; EXPERIENCE Flow 2 names the same student "Alex Rivera" with he/him pronouns. Teacher greeting is "Welcome back, David" though the protagonist is "Mr. Chen".
Fix: Keep persona names/pronouns verbatim from PRD or reconcile deliberately.

2. Token completeness

THIN

All color tokens carry hex values. Typography, rounded, and spacing are defined. But two frontmatter-to-prose contradictions are load-bearing, and cross-reference syntax is inconsistent.

CRITICAL

Badge token contradiction: filled vs tinted

DESIGN.md lines 63–74 vs 166–173, 210
Frontmatter badge-pending/absent/graded are filled (background = semantic color, foreground #FFFFFF), but the prose spec explicitly stipulates tinted badges ("light-background variant, not white-on-color") and the Do’s/Don’t bans "filled badges." A consumer resolving frontmatter would render filled pills that violate the brand’s own discipline.
Fix: Rewrite frontmatter badge tokens to tinted values (e.g. #FDF5E6/#9E8A5A) or remove color from frontmatter and let prose own badge colors.
CRITICAL

Skeleton token contradiction: border vs background

DESIGN.md line 76 vs line 177
Frontmatter skeleton.background = ‘{colors.border}’ (#E5E2DD) but prose says ‘{colors.background} (#FAF8F5) fill’. Two different fills for the same component.
Fix: Align to one value (prose’s warm-paper #FAF8F5 fill reads intentional) and update frontmatter.
MEDIUM

Cross-ref syntax inconsistency

DESIGN.md line 197
{rounded.full} (dot, used in frontmatter) vs {rounded/full} (slash, in progress-bar prose). Per design-md-spec the syntax is {path.to.token} with dots.
Fix: Normalize to {rounded.full}.
MEDIUM

Five prose-only components untokenized

DESIGN.md §Components
inline-banner, empty-state, exam-question-card, progress-bar, timer have visual specs in prose but no frontmatter components entry. Story-dev cannot resolve them against the token system.
Fix: Add frontmatter components entries (at least color/radius) for each.
LOW

Light mode only; dark mode unaddressed

DESIGN.md
No -dark tokens and DESIGN.md never addresses dark mode. Defensible if dark is out of scope but the intent is uncommitted.
Fix: State “light mode only in v1” explicitly.

Accessibility review

review-accessibility.md

The spines establish a solid accessibility floor with clear intent and specific WCAG references, but contain a critical contradiction in the badge token spec, a non-compliant timer warning color, and several gaps around exam full-screen mode focus trapping, skeleton loading announcements, and toast auto-dismiss pausing. The exam-taking surface needs the most reinforcement.

CRITICAL

Badge token mismatch produces AA failure

DESIGN.md lines 63–74 vs 168–173
Frontmatter defines badges as white-on-color (e.g. foreground #FFFFFF on warning #9E8A5A), yielding ~2.7:1 contrast — a WCAG failure. Component spec defines tinted-background badges with dark text.
Fix: Delete or correct frontmatter badge tokens to match tinted-background spec.
HIGH

Timer warning color fails AA contrast

DESIGN.md lines 199–201
Danger #9E6A6A on exam-surface #F5F2ED yields ~4.37:1 — fails AA 4.5:1 for the 20px Georgia text. 20px weight-400 Georgia does not qualify as “large text” under WCAG.
Fix: Darken danger to #8E5555 or #7A4A4A to reach 4.5:1+.
HIGH

No focus trap in exam full-screen mode

EXPERIENCE.md lines 102, 128
Keyboard user could Tab out of the exam into browser chrome or background page content during the exam.
Fix: Specify focus-trap on exam-taking container; cycle Tab within exam surface.
HIGH

role=“application” anti-pattern on exam interface

EXPERIENCE.md line 127
Suppresses standard screen reader keyboard shortcuts. An exam with radio buttons and navigation does not justify role=“application”.
Fix: Remove role=“application”. Use standard landmarks, heading hierarchy, and ARIA attributes.
HIGH

Skeleton loading states silent for screen readers

EXPERIENCE.md line 84
Users who cannot see the shimmer encounter an empty or partially-rendered page with no indication content is loading.
Fix: Add aria-busy=“true” and aria-live=“polite” on skeleton containers.
HIGH

Missing modal/exam focus management

EXPERIENCE.md lines 78, 177
No focus-management specification after Finalize Grades modal open/close or after exam submission redirect.
Fix: On dialog open, focus moves to Cancel button; on close, returns to trigger. After exam submit redirect, focus to page heading.
HIGH

Exam auto-submit blind to screen reader users

EXPERIENCE.md line 175
Timer expiry auto-submits with no announcement. A screen reader user may not realize the exam ended.
Fix: Announce “Time is up. Your exam has been submitted.” via aria-live=“assertive” on auto-submit.
HIGH

Question sidebar has no ARIA structure

EXPERIENCE.md lines 103, 174
No ARIA roles specified. Screen readers need structure to navigate between questions.
Fix: Use <nav aria-label=“Question navigation”> with <ol>; current question with aria-current=“true”.

Edge case review

review-edge-cases.md

The happy paths are well-covered. Substantial gaps remain in permission boundary behavior (zero definition of unauthorized access UX), race conditions in concurrent grading, offline conflict resolution, missing empty states for less-common surfaces, and error handling beyond fetch/auto-save. 42 findings across 9 categories.

CRITICAL

Permission boundary behavior undefined

EXPERIENCE.md IA
No definition of what happens when a student navigates to a teacher URL (or vice versa). The spine says “they never see the other role’s surfaces” but defines no redirect, 403 page, or routing guard.
Fix: Define: server-side 403 on API; client-side redirect to own dashboard with toast “You don’t have access to that page.”
HIGH

Exam submission failure (network drop on Submit)

EXPERIENCE.md Flow 2
Student sees confirmation but server never receives it. No retry UX defined.
Fix: Define retry: “Submission failed. Retry” inline banner with submit action preserved.
HIGH

Race condition: two teachers grading simultaneously

EXPERIENCE.md Grading Table
Grades could overwrite each other with no conflict detection.
Fix: Define optimistic locking or last-write-wins with conflict banner.
HIGH

Timer expires while submit confirmation dialog is open

EXPERIENCE.md Flow 2
The confirm dialog is open, timer hits zero — undefined behavior.
Fix: Auto-close dialog, auto-submit whatever is answered, show toast: “Time expired — your exam was submitted.”
HIGH

Session expiry mid-use undefined

PRD FR-23
PRD says “session maintained until logout” but sessions time out. No expired-session UX defined.
Fix: Define expired-session redirect to login with toast.
HIGH

Pagination behavior for large lists undefined

EXPERIENCE.md §Interaction Primitives
Spine says “pagination only” but defines no page size, no UI for pagination controls, no search+paginate behavior.
Fix: Define page size (e.g. 25 rows), pagination controls, and search filtering within paginated results.
HIGH

Offline conflict resolution undefined

EXPERIENCE.md Flow 2 failure
What if teacher finalized the exam while student was offline? No sync conflict strategy.
Fix: On sync, if exam is finalized, show banner: “Your teacher has finalized this exam while you were offline.”
