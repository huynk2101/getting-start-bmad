- (decision) Design paradigm: REST API + SPA. React frontend, Express/Fastify backend, PostgreSQL with Prisma ORM. Chosen for simplicity, explicitness, and alignment with hobby-project-treated-seriously scope.
- (decision) Authentication: JWT via HTTP-only cookies. Stateless, no session store needed. Standard for SPA + REST. Role-based access enforced on backend (teacher vs student).
- (decision) Repo structure: separate repos (sms-frontend + sms-backend). Cleaner separation. Type sharing via shared TypeScript types package or manual sync.
- (decision) Frontend state: TanStack Query (React Query) for server state. Client state minimal (React Context for auth/UI state only). REST API is the single source of truth.
- (decision) Database schema: Prisma schema as source of truth, prisma migrate generates SQL. Type-safe. PostgreSQL.
- (decision) Account provisioning v1: seeded initial teacher account (seed script/env config). Teacher creates classes and manually creates student accounts. No self-registration, no admin role. Respects PRD no-admin constraint. CSV import deferred.
- (decision) Grading model: dual-path. (1) Online exams auto-score from per-question student answers (MCQ/TF have a single correct answer); teacher can override scores. (2) Manual per-student score entry for offline/other exams. Score aggregates per-question answers; finalize unlocks correct-answer disclosure.
- (decision) Exam lifecycle: availability window = scheduled start through deadline (start + allowance); full duration once started; warning + auto-submit on expiry; exam not startable after closed; submission is final (no re-take in v1).
- (decision) Offline resilience v1: deferred. Keep auto-save on each answer selection (retry on reconnect covers brief drops). No formal offline queue / offline resume in v1. PRD FR-19 offline-sync assumption downgraded to retry-on-reconnect.
- (decision) Deployment/environment v1: docker-compose for reproducibility/portability, single dev environment. Postgres in container. Cloud hosting deferred until worthwhile.
- (decision) Backend framework: Express (Node.js). Chosen for familiarity and simplicity; TypeScript throughout.
- (decision) Frontend tooling (verified on web 2026): Vite (v6) + React (v19) + TypeScript starter, React Router for routing, Vitest + React Testing Library for tests. Seed-level, not a spine invariant. TanStack Query for server state.
- (decision) Result ownership: single canonical Submission entity owns student answers + lifecycle (in-progress -> submitted -> graded); Score derived from and stored against Submission. Prevents two owners of one entity (ExamSubmission vs GradeRecord) producing an un-integratable result view.
- (decision) Shared data contract between repos: versioned sms-shared types package defines DTO shapes both consume (student-answer, score/result). Prevents clashing shared-data shapes caught only at integration.
- (decision) Question entity and management: Question belongs to and is owned by the exam/test it belongs to (no question bank v1); types MCQ/TF with a single correct answer; CRUD via backend routes. Prevents ad-hoc question data model.
- (decision) Exam schedule conflict detection: creation validates window against existing exams for same class; overlap returns 409, not saved; check in backend service layer. Prevents overlapping exam windows.
- (decision) Absent student marking: student can be marked absent for an exam/test; removes from score-entry input, sets result status to absent; property of Submission/Score record not separate entity. Prevents absent students graded or ambiguous.
- (decision) Schedule model: class Schedule models recurring day/time slots (e.g. Mon/Wed 09:00), belongs to Class, source for teacher daily overview and student schedule. Prevents schedule stored ad-hoc across classes.
- (version) Version re-pins after web verification 2026: Node 24 LTS, TypeScript 7, Express 5, Prisma 7, PostgreSQL 18, Vite 8, React Router 8, Vitest 4. React 19.x and TanStack Query 5.x unchanged (current stable lines).
- (event) spine finalized
