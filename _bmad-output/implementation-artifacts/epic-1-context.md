# Epic 1 Context: Foundation & Authentication

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Establish the full development foundation — monorepo scaffolding, design tokens, base component library, complete database schema with seed data, Docker environment, and JWT-based authentication with role-based access control. Every subsequent epic depends on the infrastructure, design system, and auth layer built here.

## Stories

- Story 1.1: Project Scaffolding & Docker Environment
- Story 1.2: Design Tokens
- Story 1.3: Base Components
- Story 1.4: Database Schema & Seed Data
- Story 1.5: User Login
- Story 1.6: Role-Based Access Control

## Requirements & Constraints

- Monorepo with three packages: `sms-frontend` (React + Vite), `sms-backend` (Express + Prisma), and `sms-shared` (versioned TypeScript types consumed by both repos).
- Docker-compose for local dev: PostgreSQL 18, Express backend, Vite dev server. `prisma migrate` runs inside the container on startup.
- Authentication uses stateless JWT in HTTP-only cookies — no localStorage, no server-side session store. On login, the token is set as a cookie and the user is redirected to the role-appropriate dashboard (teacher or student). On JWT expiry, the cookie is cleared and the user is redirected to login.
- Every protected backend route must validate the JWT and enforce the caller's role. Students hitting teacher-only endpoints get 403; teachers hitting student-only endpoints get 403. No JWT present returns 401. All errors use the standard envelope `{ "error": { "code": "STRING", "message": "STRING" } }`.
- Database schema must cover: User (with TEACHER/STUDENT role enum), Class, Schedule, Exam, Question, Submission, Score — with correct foreign keys and indexes. All timestamps stored UTC; the API layer handles timezone conversion. A seed script creates a default teacher account with known credentials, one class with a schedule, and two enrolled students.
- Design system: light mode only in v1 (`color-scheme: light`). Desktop-first responsive layout (lg/md/sm breakpoints; sidebar collapses below 1024px; tables stack below 768px).

## Technical Decisions

- **Backend:** Express 5 on Node.js 24 LTS, TypeScript 7. Prisma 7 ORM; schema is the source of truth — no raw SQL migrations.
- **Frontend:** React 19, Vite 8, React Router 8. TanStack Query 5 manages all server state; React Context is only for auth/UI state (theme, modals). No Redux or Zustand.
- **Database:** PostgreSQL 18. IDs are UUIDs generated by Prisma. Paginated list endpoints default to page size 20. Response shape for paginated lists: `{ "data": [...], "pagination": { "total": N, "page": N, "pageSize": N } }`.
- **API error envelope:** Every error response is `{ "error": { "code": "STRING", "message": "STRING" } }` with appropriate HTTP status codes (400, 401, 403, 404, 500).
- **Account provisioning:** No self-registration. Teacher accounts are created via seed script or environment config. Students are created manually by teachers. CSV import deferred to v2.
- **Shared types:** `sms-shared` is a versioned package defining DTO shapes both repos consume. Cross-repo data shapes (student answers, score/result payloads) are defined here first, with a version bump on any change.

## UX & Interaction Patterns

- **Modern & Minimal visual direction:** Cool slate background (`#F8FAFC`), clean white card surfaces, single crisp blue accent (`#2563EB`) as the only interactive color, system sans-serif for everything (no serif — weight 600 for headings, 500 for labels, 400 for body). Flat and deliberate; no gradients, no shadow depth hierarchy.
- **Three-tier radius:** 6px for inputs, 10px for cards/buttons (default), 14px for modals/dialogs, 9999px for status badges only.
- **Base components required in this epic:** `button-primary`, `card`, `badge-pending`/`badge-absent`/`badge-graded`, `skeleton`, `toast`, `empty-state`. Skeleton shimmer replaces all spinners — matching the expected layout shape, with `aria-busy="true"` on the container. Toasts auto-dismiss at 3 seconds, bottom-center. Empty states are direct ("No classes scheduled today — enjoy the break."), never apologetic.
- **Teacher and Student navigation are completely separate** — no role-switcher. Each role has its own top-nav surfaces.
- **Login page:** Inline error banner (not modal) with `role="alert"` for invalid credentials: "Invalid username or password." Focus moves to the error on failed submit.
- **Accessibility floor:** WCAG 2.2 AA contrast. Visible blue focus ring on all interactive elements. Semantic HTML for tables, forms, tabs with ARIA attributes. `prefers-reduced-motion` disables all transitions (skeleton shimmer, toast dismiss). Tab order matches visual reading order on every surface.

## Cross-Story Dependencies

- Stories 1.2 (Design Tokens) and 1.3 (Base Components) must be complete before any feature epic's UI work begins — every subsequent story composes from the token system and component library.
- Story 1.4 (Database Schema) must be complete before any epic that reads or writes business data (Epics 2–7). The seed data provides the initial teacher account used for login testing in Story 1.5.
- Stories 1.5 (Login) and 1.6 (RBAC) must both be complete before Epics 2–7, as every feature endpoint requires authenticated, role-gated access.
- The `sms-shared` types package (Story 1.1) is consumed by all subsequent frontend/backend work — any schema or API shape change must land there first with a version bump.
