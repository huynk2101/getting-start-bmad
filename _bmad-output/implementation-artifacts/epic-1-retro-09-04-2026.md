## Phase 2 — Analyze

### Aggregate Views

#### Architecture Delta

The range introduced a layered auth middleware stack: `requireAuth` (JWT decode + req.user attachment) in `auth.ts` and `requireRole` (role check) in `authorize.ts`. The two are composed at the route level in `protected.ts` — a clean pipeline pattern that Epics 2-7 routes will replicate.

**New dependency edges introduced:**
- sms-backend: jsonwebtoken, cookie-parser (runtime); @types/jsonwebtoken (dev)
- sms-frontend: react-router-dom (runtime)
- sms-shared: LoginRequest, LoginResponse, UserDTO shared types

No cross-cutting dependency violations observed. No cycles introduced. Backend layer boundary (routes -> middleware -> prisma) is respected.

Source: `sms-backend/src/index.ts:1-6`, `sms-backend/src/middleware/auth.ts`, `sms-backend/src/middleware/authorize.ts`

#### Duplication Map

**Finding F-1 — Inline role type duplicated in auth.ts and authorize.ts** (disposition: defer)
"TEACHER" | "STUDENT" is spelled inline in `auth.ts:14` (JwtPayload.role) and again in `authorize.ts:4` (requireRole parameter type). sms-shared exports UserDTO but not a shared UserRole type. This duplication will multiply as Epic 2-7 routes add role checks.
Source: `sms-backend/src/middleware/auth.ts:14`, `sms-backend/src/middleware/authorize.ts:4`, `deferred-work.md:170-171`.

**Finding F-2 — Error shape repeated inline, no shared helper** (disposition: accept as-is)
Both auth.ts and authorize.ts construct `{ error: { code, message } }` as inline literals. Pre-existing pattern; remediation belongs with a dedicated error-handling story.
Source: `sms-backend/src/routes/auth.ts`, `sms-backend/src/middleware/authorize.ts:9-23`, `deferred-work.md:187-188`.

#### God-Class / Size Growth

No file grew to a problematic size. Largest new source file is `sms-backend/src/routes/auth.ts` at 148 net lines. `sms-frontend/src/App.tsx` grew 81 net lines — now carries routing, auth wiring, and component composition together.

**Finding F-3 — App.tsx combining routing, auth wiring, and composition** (disposition: accept, watch)
Manageable now; becomes a concern when Epic 2+ adds route trees. Recommend extracting a RouterConfig component when routes exceed ~8 entries.
Source: `sms-frontend/src/App.tsx`, git_evidence.py net: 81.

#### Pattern Divergence

**Finding F-4 — No backend test infrastructure** (disposition: fix-now — action item)
Stories 1.1-1.6 have zero backend test files. sms-frontend has Vitest + RTL (19 tests, installed in Story 1.3), but sms-backend has no test framework, no test script in package.json, and no test files. Auth routes, middleware, and database operations are entirely test-blind.
Source: `deferred-work.md:131-132, 161-162`, spec-1-5:94, spec-1-6:83.

**Finding F-5 — Demonstrator routes unconditionally mounted** (disposition: defer)
/api/protected/teacher-only and /api/protected/student-only are mounted in all environments. Intentional per spec; could be gated by env flag in a later hardening pass.
Source: `deferred-work.md:176-177`, `sms-backend/src/routes/protected.ts`.

**Finding F-6 — Frontend API base path hardcoded via Vite proxy** (disposition: defer)
No VITE_API_BASE env var; all fetch calls use bare /api/ paths. Breaks in non-Vite deployments.
Source: `deferred-work.md:143-144`.

**Finding F-7 — Two routing sources of truth in the frontend** (disposition: defer)
useSyncStoreToUrl reconciles old route state store with React Router. Planned transition state per spec Design Notes.
Source: `deferred-work.md:146-147`, spec-1-5 Design Notes.

#### Spec-to-Implementation Reconciliation

All six story specs reviewed against as-built code. No silent requirement drops or unspecified behavior. Every deviation was caught at review time and explicitly deferred in deferred-work.md. Key decisions correctly locked in:
- JWT payload shape (userId, username, role, iat, exp) — matches auth.ts:11-17
- Cookie settings (httpOnly: true, sameSite: strict, dynamic secure) — matches auth.ts post-patch
- Error envelopes { "error": { "code": "STRING", "message": "STRING" } } — consistent across all routes
- requireRole variadic + compile-time tuple type — matches authorize.ts:3-4 post review patch
- Demonstrator endpoint response { data: { ok: true } } — matches protected.ts:15, 27

**Accepted deviation on record:** Story 1.6 spec says "reuse, do not modify" for requireAuth, but Story 1.5 review pass correctly added payload validation and production guards — implementation is better than spec. Propose spec reconciliation as a follow-on.
